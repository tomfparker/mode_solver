# M2 benchmarks: accuracy and speed of the mode solver

Date: 2026-10-10. Machine: Intel Core i5-6500T (2016, 4 cores), under moderate background
load, native Python (numpy 2.4.6, scipy 1.18.0). The browser (Pyodide) is about 1.5× slower
(docs/spike-m0.md). Times are best of 3 and include the coarse pass used for extrapolation.

## What is compared

Five structures (`solver_py/tests/cases.py`) at 1550 nm, with indices from the material
library, each in a fixed window that stops inside the oxide:

- `soi_strip`: 500 × 220 nm silicon wire in oxide.
- `sin_strip`: 1200 × 800 nm Si₃N₄ strip in oxide (the app's default example).
- `soi_rib`: 500 nm silicon rib, 130 nm etch, on a 90 nm slab.
- `ridge_iso`: 300 nm Si₃N₄ ridge with 60° sidewalls on a 300 nm slab, air-clad.
- `ln_ridge`: the same ridge geometry in X-cut LiNbO₃ (anisotropic).

Analytic cases (slab TE/TM, uniaxial slab, step-index fibre LP01) are covered by
`solver_py/tests/test_analytic.py` and are not repeated here.

- **femwell** is the primary reference for isotropic cases: second-order elements on a mesh

- **Tidy3D** runs locally without subpixel smoothing, so high-contrast cases are biased even

  strip and ridge. It is the only reference for the anisotropic LN ridge; there our result
  is also supported by the analytic uniaxial-slab test and by `ridge_iso` (same shape,
  checked by femwell).

## Conclusions

1. **Two-mesh extrapolation is the best speed/accuracy trade.** The standard preset with
   extrapolation is more accurate than a single mesh with cells 3× smaller (×0.4), in about
   a fifth of the time.
2. **Presets** (set in `solver_py/modesolver/ui.py`):
   - *Fast* (×2.0): worst error 2.6e-3, 185–240 ms.
   - *Standard* (×1.3, the default): worst error 6.7e-4 (SOI strip TM0), 350–470 ms. Meets
     the ~1e-3 target on every case with margin.
   - *Fine* (×0.8): worst error 5.7e-4, 0.55–1.0 s. Little gain on the hardest case, so the
     default stays at Standard, in line with preferring speed.
3. **Mode size** (1/e² width of |E|² through the peak) is within 5% of Tidy3D's fields on all
   five cases at ×1.4, ×2.0 and ×2.8 (target: 10%); the ×1.3 default passes the 10% test in
   `test_reference.py`.
4. The hardest mode is the SOI strip's TM0: its field varies fastest inside the 220 nm
   silicon, so it sets the mesh requirement.

## Caveats

- Timings were taken on a loaded machine and vary by ±20% between runs.
- Errors are not monotonic in the scale factor: cell counts across a shape are rounded to
  integers, which shifts the result at the 1e-4 level.
- Only fundamental modes are compared. Higher modes near cut-off and slab/window modes depend
  on the boundary treatment, which differs between solvers.
- The references are open-source solver runs, not measurements. The Lumerical values the
  maintainer planned to supply would be a useful independent check.

## Reproduce

```
.venv-bench/bin/python benchmarks/run_reference.py     # references (slow; needs tidy3d + femwell)
.venv/bin/python benchmarks/sweep.py --md              # this table
.venv/bin/pytest solver_py/tests/test_reference.py     # pass/fail against the targets
```
